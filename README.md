Projeto Módulo 3 – Low Code/No Code/Vibecode
📌 Desafio Escolhido

O grupo escolheu desenvolver um MVP (Minimum Viable Product) de uma plataforma de gerenciamento de tarefas acadêmicas utilizando ferramentas low code/no code.

O objetivo do projeto foi criar uma aplicação simples que permitisse:


Criação de tarefas;
Organização por prioridade;
Controle de status das atividades;
Visualização rápida das tarefas pendentes e concluídas.
🖥️ Protótipo
Telas desenvolvidas
Tela de Login
Tela de Cadastro
Dashboard principal
Página de criação de tarefas
Lista de tarefas
Funcionamento do protótipo

O usuário realiza login na plataforma e acessa um painel principal onde pode criar, editar e excluir tarefas. As atividades podem ser classificadas por prioridade e marcadas como concluídas.

O sistema foi pensado para auxiliar estudantes na organização de trabalhos, provas e atividades da faculdade.

Coloque os prints das telas ou PDF do protótipo na pasta /docs.

⚙️ Plataforma Utilizada

Plataforma escolhida: Bubble

Justificativa da escolha

A plataforma Bubble foi escolhida por permitir a criação de aplicações web de forma visual, sem necessidade de programação avançada. Além disso, oferece:

Interface intuitiva;
Criação rápida de banco de dados;
Sistema de workflows automatizados;
Facilidade para publicar protótipos funcionais.
✅ Vantagens Identificadas
Desenvolvimento rápido do protótipo;
Interface visual simples e intuitiva;
Integração fácil com banco de dados e automações;
Menor necessidade de conhecimento avançado em programação;
Facilidade para testes e validações do MVP.
⚠️ Limitações Encontradas
Customização limitada em algumas funcionalidades;
Dependência da plataforma utilizada;
Algumas ferramentas avançadas são pagas;
Dificuldade em implementar funcionalidades muito específicas;
Limitações de desempenho na versão gratuita.
📚 Reflexão Crítica

O grupo percebeu que as plataformas low code/no code facilitam bastante o desenvolvimento inicial de aplicações, principalmente para prototipagem rápida.

Entretanto, também foram identificadas limitações relacionadas à personalização e aos recursos disponíveis gratuitamente. Para contornar essas dificuldades, o grupo buscou simplificar algumas funcionalidades do sistema e utilizar elementos nativos da plataforma.

Como solução criativa, foram utilizados workflows automáticos e componentes visuais reutilizáveis, reduzindo a complexidade do desenvolvimento.
